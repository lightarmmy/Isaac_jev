# 高层规划与导航测试

用于用户要求评估 Jev 战斗以外的功能，同时仍让 Jev 接管战斗。使用正常的 start_autoplay/execute_plan/wait_for_decision 流程，保持原战斗交接，不切换为人工战斗，不改游戏状态生成测试数据。

## 测试范围与执行

1. doctor 检查游戏与 L40S，CLI 的 check 确认帧推进和启动条件。确认实验游戏存活、manual、未暂停；记录种子、楼层、初始血量和背包。死亡后需用户准备新局；存活的暂停局可恢复原局。测试期间保持游戏前台，开始会话。
2. 用当前可见地图和候选连续选择目标。优先测试宝箱房、商店查看和适合拾取的掉落；按资源、可达路径和未完成测试项选择顺序。只提交工具生成的 action_id。
3. 尽量验证至少三次过门，并在可用时包含已清空房间的回访。遇敌或残留弹幕仍由 Jev 战斗，持续等待至 planning 再选下一个目标。
4. 宝箱房验证实际获得一个道具；商店读取商品和价格并完成查看，不购买，包括免费商品。普通掉落存在时验证拾取；没有合适掉落则标记未测，不生成或伪造资源。
5. 观察 execution.navigation：无障碍路段是否直达、门前是否对齐、绕障是否可达、是否反复切换方向或长时间顶墙。记录 blocked 原因及人工帮助次数。
6. 已达成本轮可用测试项后，在清空且无残留弹幕的房间 stop_autoplay。战斗卡住阻碍后续测试时报告战斗阻塞；需要中止危险战斗时先提示用户按 Esc 暂停或主动接管，避免把角色释放在敌人旁边后无人操作。F8、暂停、死亡或断线已停止的会话不自行恢复。

当前仍为首期范围：走门、普通掉落、宝箱道具、商店只查看。不测试购买、开箱、按钮、炸弹、主动/卡牌/药丸使用、楼梯/传送。持有主动道具不等于使用它。

## 评价

分别记录每个目标的尝试次数、完成次数、实际前后状态、失败原因，以及自动操作需要人工帮助的次数。结果必须来自任务完成事件、房间 ID、背包/血量/道具变化；命令受理、地图显示或某次坐标靠近不是完成证明。

| 项目 | 完成证据与可记录指标 |
|---|---|
| 连续过门 | 原房间/目标房间/实际房间；成功次数、导航耗时、路径是否摆动 |
| 绕障与回访 | 路径与实际位移；是否绕开障碍、是否重复失败或需要人工帮助 |
| 普通掉落 | 目标消失且对应资源/道具发生变化；成功/失败/不存在 |
| 宝箱房道具 | 道具/库存前后变化；知识是否有来源、取舍是否符合当前状态 |
| 商店查看 | 读取商品和实际价格；资源未因购买改变、未误碰商品 |
| 高层决策 | 目标合法性、钥匙等资源约束、重复无效目标次数、知识缺失处理 |

导航耗时只算实际导航段，排除 Jev 战斗、清房等待、暂停、用户切回聊天和高层查询时间。若记录规划决策耗时，说明它是否包含工具/百科查询；不要把它当作纯模型推理时间。战斗清房、受伤、停留和耗时另列，作为可能阻塞测试的背景，不计入导航失败率。

原始录像始终保留战斗和非战斗状态。结合 .local/isaac-skill/events.jsonl 的 task_started/task_completed/task_blocked、navigation_path、combat_started/planning_required 与录像识别阶段。某个房间几秒后已 clear 不能证明它本来没有敌人；按事件和连续状态确认。

最终报告给出每项“通过/失败/未测”、实际次数和证据；未达到的测试项解释是本层没有该场景、路径失败还是战斗阻塞。不要声称完成了整层或某项功能而没有对应证据。

拾取后 UID 可能仍是空台座或被交换下来的主动道具。以道具/资源实际变化及内容变化核对，不能把实体仍存在当作尚未拾取；原始录像中首次获得的时间与任务结束时间分别记录，避免把完成判定错误后的无效移动算成取物速度。同一位置连续出现相同的起点重叠/无法起步错误时，先只读诊断；更换远端目标不能解决起点被困的问题。

`execution.navigation.stage=settling` 表示执行器正在同一任务内等待动量衰减，应继续等待，不重新提交目标。每轮恢复最多 10 个推进帧，累计最多 30 帧。最终 blocked 的 `failure.reason_code/recoverable` 区分恢复超预算与静态不可达；recoverable 不代表可以在状态不变时无限重试。门洞站位允许走已知可通行门的通道，不会把实际坐标吸附或传送到网格。

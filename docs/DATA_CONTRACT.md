# 原始数据与战斗模型输入

协议版本 1；动作版本 `move9-shoot5-active-edge-v2`；当前特征版本 `combat-projectiles-history-conditioned-v3`。本文件以下原始采集说明仍适用；当前策略、结果条件及三个输出分支的详细契约以 [CONDITIONED_POLICY.md](CONDITIONED_POLICY.md) 为准，后文 v2 策略/训练描述作为旧版记录。

## 原始采集

使用 REPENTOGON 的 `MC_PRE_UPDATE` 记录回调处的原始状态和输入，更新频率为 30 Hz。实机发现 `MC_USE_ITEM` 会早于同帧的采样：例如帧 N 的道具使用事件已出现，帧 N 的充能已经扣除。因此示范转换必须以观测帧 N 配对操作帧 N+1；同房间、同整局且逻辑帧连续才生成样本。暂停期间没有新的逻辑帧，不计作战斗样本。

每个 JSONL 帧包含 run_id、room.id、game_frame、seq、capture_phase、mode。mod 0.2.0 起，run_id 按种子稳定分组：继续同一局、重载 mod，以及重玩同一种子均归入同一数据集合。种子和 run_id 不会进入策略输入。

| 原始信息 | 已实现的字段 |
| --- | --- |
| 玩家 | 世界位置、速度、碰撞尺寸、人物类型、死亡、飞行、控制可用、红心/魂心/骨心/腐心、伤害、移速、弹速、射速延迟、泪弹相关属性 |
| 主动道具 | 主要槽位 ID、解析后的英文名称/描述及原始本地化键、当前/电池充能、最大充能、充能类型、基础就绪估计 |
| 资源与道具 | 金币、钥匙、炸弹、饰品、已持有被动道具 ID/数量/原始描述、卡牌和药丸颜色 |
| 房间 | 类型、形状、边界、网格大小、所有当前网格实体的类型/位置/碰撞/状态、门位置与开闭 |
| 全部当前实体 | 稳定身份、类型/变体/子类型、位置、速度、碰撞、血量、阵营、存活、可见性、动画与帧、NPC 状态、弹幕轨迹属性、激光端点/角度/半径、炸弹和效果信息 |
| 人工输入 | 连续移动/射击输入、主动道具按住状态及按下边沿、炸弹/卡牌边沿 |
| 实际执行 | 最近 AI 指令、所属观测帧、有效期、请求 ID、执行模式和命令回执 |
| 事件 | 开局、伤害、真实 item_used 事件；action_started 输入开始事件；录制丢帧和错误计数 |

玩家与实体的 128 位泪弹标志存为 `encoding=bitset128`、`low_hex`、`high_hex`，保留所有位，避免被 JSON 浮点数截断。原始本地化键仍保留，名称解析失败时可以审计。

原始当前实体不按“最近 12 个”截断。采用后台 gzip JSONL 录制，保存全部当前房间实体用于重做特征。队列或网络背压造成的丢帧会计数，不把缺帧当作完整数据。

部分字段可能在当前游戏 API 下不可用，会缺省；例如炸弹倒计时读接口要在实机确认。原始短描述也不等于完整道具机制。初版为少量道具加入手写效果文本，其他道具需要补规则和示范。

复杂激光、地面效果、追踪弹和特殊武器虽被原始记录，当前几何特征并未完整处理其所有行为。首版推理验收要限定场景，不能声称支持全游戏。

## 策略输入

`features.py` 将完整帧转换为有界文本和数值向量：

- 玩家归一化位置/速度/血量与战斗属性。
- 最近 4 个敌人的相对位置/速度/血量/状态/可伤害信息。
- 对全部敌人与敌方投射物计算 9 个移动方向的短期风险摘要。
- 3 帧位置的边界与网格接近距离、6 帧匀速相对运动近似。
- 当前主动道具及效果、充能与上一动作。
- 固定版本战斗规则。

风险摘要是近似特征，不是自动决定动作的规则控制器。飞行碰撞、地面持续伤害、弯曲激光等需要后续专门扩展与验证。未来生成信息、隐藏地图与内部种子不进入模型提示或数值特征。

输入超过 tokenizer 的长度预算时明确报错，不静默截断关键状态。导出模型保存规则哈希、数值特征名称顺序、归一化、主干版本和 tokenizer 修订。

## 输出

45 个联合动作：9 种移动 × 5 种射击。另一个独立二分类头输出是否触发主动道具，可以与移动、射击同时执行；它不是第 46 个互斥动作。

动作的 `hold_frames` 为 1–6；观测有效期独立设为观测帧之后 6 帧。首次实际玩家输入查询时开始计时，最终停止帧为首次查询帧加保持时长与观测有效期限的较小值。不能通过重新标记旧观测延长有效期。

主动触发仅在首次实际输入查询所在的一个逻辑帧有效，命令请求去重。模型正样本不足或道具未在训练中出现时不自动启用主动使用。计时和特殊充能的可用性仍由游戏实际判定。人工主动使用的事件采集已在实机验证，自动主动输入仍需对应实机验收。

## 数据集划分与训练

仅 manual、单人且非死亡的连续战斗帧对生成示范样本。观测状态来自前一帧，移动/射击标签来自后一帧；模型中的上一动作来自观测帧已发生的人工输入。原始 AI 帧仍可记录但不会直接当作人工正确标签。

按 run_id 的 SHA256 分桶：0 测试、1 验证、2–9 训练。同一整局的相邻帧不会泄漏到其他集合。需要采集多个独立整局，保证训练与验证都有样本。

主动正标签须同时满足：后一帧有人工按下边沿、观测帧的主要主动道具就绪、后一帧记录到匹配道具和主要槽位的真实 `item_used` 事件。下采样保留这些正样本；无效空格尝试可以审计，但不作为成功使用标签。训练以交叉熵学习联合动作，以加权 BCE 学习稀少的主动触发；测试分别报告移动射击准确率和主动精确率/召回。离线指标不能代替实机清房、受伤、延迟与接管次数。

会话元数据的 `purpose=diagnostic` 表示控制探针、人工按键测试和调试道具实验，数据转换默认排除这些会话。`purpose=demonstration` 才用于个人游玩示范。完整 gzip 文件须正常结束后再转换；`record stop` 会排空写入队列并关闭录制，bridge 可以继续接收状态。

## 输入和输出

- 当前最近 8 个敌方弹幕：相对位置、速度、尺寸、高度、下落速度/加速度和标志。其余弹幕仍参与九个移动方向的风险估计，文本给出省略数量。
- 历史为 3、9、18 个逻辑帧前（约 0.1、0.3、0.6 秒）的摘要：玩家相对位移、速度、生命、过去移动/射击/主动使用、敌人及弹幕数量、最近敌人和两个最近弹幕的位置与速度。缺帧、换房、换局、换模式和重新连接时重置；不推测缺失历史。
- 训练文本最后指定实际观察结果条件；部署文本固定 `Desired outcome condition: positive`。条件也有三个固定数值指示位，便于小头使用。
- 主动道具 ID 保留在文本中，不作为连续数值。上一移动和射击使用 one-hot。数值已按物理尺度缩放并限幅，不再按单局的样本标准差进行 z-score，避免常量字段在另一局爆大。
- 输出为 `move: 9`、`shoot: 5`、`active: 1`。游戏指令仍使用 `move_id*5+shoot_id` 的 45 类编号，协议无需更改。
- 历史直接注入文本，目前不使用 GRU。输入示例见 [example_policy_prompt_v3.txt](example_policy_prompt_v3.txt)。

冻结文本主干 → 文本 LayerNorm → 拼接 165 维数值 → Linear 到 256 → GELU → 三个线性输出。只有文本向量做 LayerNorm，不把文本与数值混在同一个归一化层中。

## 自动标注

默认结果窗口为下一帧动作之后的 30 个逻辑帧（1 秒），可设为 1–150 帧。结果只写入训练标签及结果条件，不进入当时的状态或历史。

| 条件 | 初版规则 |
| --- | --- |
| positive | 当时存在观测威胁，未来窗口完整，未观察到实际伤害或歧义生命变化，近期也没有受伤事件 |
| negative | 之后的窗口中，玩家伤害回调与真实生命损失/死亡相互印证，且伤害 flags 为 0 |
| unknown | 窗口截断、伤害回调但未证实扣血、生命转换、特殊 flags、近期受伤可能处于无敌期、缺乏威胁或控制不可用 |

同动作帧的伤害回调可能早于按键采样，不归因给该动作；它作为歧义证据处理。敌人受伤不是玩家受伤。其他 mod 取消伤害、献血/交易、特殊角色和隐含健康机制可能影响标注；非零 flags 先保守归 unknown，不能宣称已完全区分所有伤害原因。

这是“观察到的轨迹结果条件”，不是单次操作正确性的证明。数秒后的受伤受中间操作影响很大；负样本权重随受伤延迟从约 1 降至 0.25，unknown 权重为 0.25，positive 为 1。移动/射击交叉熵按此权重训练全部保留样本，主动头仍使用原有稀少正样本门槛。没有反事实轨迹，不进行 DPO，也不把正负标签称为真实奖励或强化学习。

未掉血不代表瞄准正确、输出足够或动作最优。下一阶段应分别添加命中/敌人生命变化与移动伤害指标，并核对实体消失、敌人生成和治疗等混淆因素。

## 训练和评估

```powershell
.venv\Scripts\python.exe -X utf8 run.py prepare-dataset recordings --output datasets/combat-v002 --stride 3 --validation-run isaac-seed:2312680804 --outcome-window-frames 30
```

```bash
bash scripts/train_l40s.sh datasets/combat-v002 artifacts/combat-v002
```

训练与验证依旧按完整 run_id 分组。未来标注和过去历史都限制在同一录制会话的连续房间片段；不拼接重载、继续或重录的数据。两种编码都保存在数据行：实际结果条件的 `prompt/numeric` 和固定 positive 的 `deployment_prompt/deployment_numeric`。

导出评估分别包含：实际条件下模仿、固定 positive 全部样本、固定 positive 下的观察 positive 子集、按观察结果分类的指标；移动/射击分别报告准确率，联合概率的 NLL 为两者 NLL 之和。优先用 positive 验证样本选择模型；不存在时明确降级为条件模仿指标。

固定 positive 不应被要求复现 negative 示范；这部分动作一致率不是优化目标。离线结果不能验证它是否能避免受伤，还需独立测试局及实机影子/控制实验。

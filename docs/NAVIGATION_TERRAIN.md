## 已确认的两种问题

旧导航每帧重算 A*，把玩家映射到最近网格中心，再用大于 3 像素的坐标偏差直接决定按哪个方向。角色惯性和输入延迟让它反复越过中心、改变上下方向。85 房离开前的录像中，导航先向右下走，之后反复右上/右下切换；不是实际最短路径要求蛇形。

86 房战斗持续向右顶障碍，属于策略的地形理解/示范问题，九种移动方向本身可以表达绕障。当前 v004 的 `move_estimates` 和数值 `*_grid_gap` 仅估算候选方向三帧后的点到障碍中心的距离，减去 20 像素；没有扣玩家半径、没有扫过完整路径，也没有表达局部障碍布局或“此方向立即走不通”。

复盘中的 2.6 Hz 与 17.1 Hz 混合了不同阶段。85 房 AI 战斗帧为 2813–2907，共 95 帧、约 3.135 秒，随后清房等待；不能将整间房的 38 秒都当作战斗。按实际 `applied_controls` 帧键去重：85 房战斗输入查询覆盖约 95.8%，86 房约 99.4%；两间房战斗指令发送间隔中位数均约 57.6 ms。因此这组数据没有显示六倍的战斗调度差异。当前文件未封存，这些是已写入部分的统计。

## 本次导航行为

- 无障碍时，从实际位置直接走向目标，不绕网格中心。有障碍时 A* 搜索安全通道，再合并可直达的路段。
- 固定当前路径，沿路径单调前进。碰撞分布或目标显著变化时重新规划；不会每帧跳回最近网格中心。
- 障碍按网格矩形处理，并按玩家尺寸扩张；检查整个移动段。碰撞网格、房间形状、坑/飞行状态、商品、机器和不支持交互均参与避让。
- 根据位置、速度与回执估计输入延迟，计入已下发的按键；接近转角/门时提前释放按键，并缩短保持时间。
- 门前先到房内的对齐点，横向偏差和横向速度足够小时，沿门的朝向直行通过。不会在尚未对齐时斜推向墙或门框。

`get_execution_status/observe_game` 的 `execution.navigation` 包含路径、路点进度、approach/align_door/cross_door 阶段及输入延迟估计。重规划记录在 `.local/isaac-skill/events.jsonl` 的 `navigation_path`，已有动作发送与回执日志继续保留。

95 项回归测试通过：包括无障碍直行、录像中的两个偏移起点、绕石头且不碰撞、地形变化后重规划、门前对齐，以及 0.7/1/1.3 移速与 1/2/3 帧输入延迟的组合。测试使用近似惯性；实机走门效果仍需复验。只更新 Python 工具服务，无需重载 0.4.2 模组。

## 下一轮 Jev 输入

建议组合局部布局与派生几何信息，而不是只追加一条自然语言建议：

| 信息 | 用途 |
|---|---|
| 附近障碍的相对坐标、类型和大小 | 区分一块石头、整排石头、窄通道及转角 |
| 玩家尺寸、飞行状态 | 正确判断碰撞与坑的可通过性 |
| 每方向可走距离、立即受阻标记及原因 | 明确表示右侧已经接触实心格等情况 |
| 局部占用矩阵 | 保留可绕行的空间结构；可作为数值输入，文本用压缩行编码 |
| 物理短时历史与接触状态 | 区分停留、滑行、受阻及刚完成绕障，不依赖前一次按键标签 |

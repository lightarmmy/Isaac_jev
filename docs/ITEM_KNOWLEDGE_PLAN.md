# 灰机 Wiki 道具字典与自动补库方案

2026-11-24。属于首个 demo 设计，尚未安装 dsh 插件或写入实际道具条目。

主要来源为用户指定的 https://isaac.huijiwiki.com/ 。技能定义检索、读取和补库流程，项目知识服务维护结构化条目，跨房间、跨游戏局复用。

## 读取流程

```text
mod 识别道具类型、ID与可见名称
  → get_item_details 批量查项目字典
  → 命中：返回效果、来源与知识修订
  → 缺失/过期：wiki_search 定位对应页面
  → wiki_read 读取正文并确认类型、ID、游戏版本
  → DeepSeek 提取重要效果与短依据
  → knowledge_upsert 校验结构及页面身份，原子写入字典
  → 返回新条目，继续选道具/看商品
```

搜索可以组合中文名、英文名、别名和 ID，来源优先限定在灰机 Wiki。道具、饰品、卡牌等分别匹配；相同数字 ID 不是同一个物品，不能只用名称或一个裸 ID 做字典键。

页面身份和适用版本核对后才将关键效果标为可用。没有读到的数值、触发条件或相互作用留 unknown。网页搜索摘要可保存为 partial，不能标成已读过完整页面。

## 字典内容

建议键为 `game_version:item_kind:item_id`，名称及别名作为检索索引。语言和页面版本在条目内保存，避免同一条目因不同名称重复。

| 字段 | 含义 |
| --- | --- |
| item_kind / item_id | 游戏中的类别与 ID |
| names / aliases | 中文、英文及常见别名 |
| game_version / applies_to | 当前游戏与资料适用版本；不同 DLC/补丁差异保留 |
| item_type / quality | 主动/被动等类型和品质，有依据时填写 |
| summary / effects | 主要效果、触发条件、代价/副作用 |
| stat_changes | 有资料支持的数值、运算含义和条件，未确定时留空 |
| synergies | 对当前构筑有用的重要组合及限制，按需逐步补充 |
| sources | 页面 URL、标题、可取得的页面 ID/修订、读取时间、支持该字段的短依据 |
| status / knowledge_revision | ready / partial / missing / stale，以及本地修订 |
| combat_support | 针对当前 Jev 版本的项目判断与原因，独立于 Wiki 游戏效果 |

推荐存储：

```text
knowledge/seed/                  可版本管理的初始/人工整理条目
.local/knowledge_cache/items/    自动查询补充的结构化条目
.local/knowledge_cache/index/    类型/ID与别名索引
.local/knowledge_cache/history/  条目修改与来源记录
```

知识服务读取时合并初始条目与后续补充，保留旧修订便于纠错。技能每次通过工具读最新条目，游戏快照附知识修订，避免对话历史中的旧效果覆盖新资料。

实际金币、血量、属性、充能及商品价格来自游戏。Wiki 条目解释效果和条件，不能以百科里的默认商店价格替换实际价格，也不把预期属性变化当作已拾取后的读数。

## 缺失时怎样处理

- 同一批宝箱房选择或商店商品批量查字典，在线只查未命中的条目。
- 同一物品的并发查询合并，已有页面与摘要按修订复用。
- 读取成功后立即持久化；后续遇到同一道具返回 cache_hit。
- 失败状态与正式效果分开存储，使用退避避免每次规划都重复请求同一个不可读页面。
- 网站暂时不可用时返回 missing/partial 及原因。DeepSeek 可继续走门、捡普通掉落、查看已知商品，或暂存未知道具选择；不补造效果。
- 初始规则和常见普通掉落可随项目预置；游戏开始时预查当前装备，降低运行中第一次查库的停顿。

## 网页工具适配

本次实测：灰机 Wiki 首页需要 JavaScript/Cookie 验证，两个常见 MediaWiki API 路径也返回 HTTP 403。因此此阶段按 dsh 可用的浏览器/网页工具读取正文来设计，不假定某条 HTTP API 已可用。具体工具调用接口仍需核对 dsh 版本。

`wiki_search` 与 `wiki_read` 为拟定插件接口；可以封装框架已有的网页搜索和浏览器读取能力。页面无法打开时返回结构化 browser_required/online_unavailable 状态，而不是把验证页或空正文入库。

知识查询不会阻塞 Jev 战斗请求。查询和选道具主要发生在安全的高层决策窗口；后台可预取已经可见的装备/商品知识。

## 首期的使用边界

宝箱房道具查询后可选择拾取、跳过或稍后回来；互斥选项在拾取后刷新。主动道具可拿取并记录，本期不自动使用。

商店返回全部可见商品名称、实际价格和已缓存效果。首期只查看商品，导航避开商品实体；普通掉落按游戏商品标记与商品区分。购买工具不进入本期可执行集合。

兼容性注释用于说明道具是否改变当前方向移动/射击语义。它属于本项目对 v004 的支持程度，不能写成“Wiki 证明模型能使用”。

验收包括：首次缺失条目能通过网页工具定位并补库；再次查询命中本地；不同类别相同 ID 不混淆；版本差异或未读正文不会被写成确定结论；查询失败仍可完成基础房间流程。

## 当前输入与决策头

真实完整输入见 [example_policy_prompt.txt](example_policy_prompt.txt)。直接 tokenize 普通文本，不使用 chat template，不生成动作文本或思维链。

文本由简短战斗协议和当前状态 JSON 组成：玩家速度、生命、战斗属性、最近四个敌人的相对位置/速度/HP/状态、投射物数量、九种移动的威胁/边界/地形距离估计、主动道具身份/充能/效果、上一动作、未建模危险数量。现有规则不是完整以撒规则或敌人/道具知识库。完整弹幕与地形保存在原始录制中，当前提示中主要使用其聚合风险摘要。

全部 1656 个提示经 tokenizer 检查为 648–955 tokens，均未超过 1024 上限。

```text
冻结 Qwen3.5-2B 文本主干 → 最后一个非 padding token 的 2048 维向量
拼接 78 个归一化数值特征 → 2126 维
LayerNorm(2126) → Linear(2126,256) → GELU
├─ Linear(256,45)：9 种移动 × 5 种射击
└─ Linear(256,1)：独立主动道具触发
```

训练参数共 560586 个。冻结主干节省反向传播开销，但每次新状态仍需要主干前向计算。

## 已发现的问题与后续方向

当前数值标准差下限为 0.001。训练局 `active_id` 恒定为 58，验证局变为 0，归一化后达到 -58；`previous_active` 的最大绝对归一化值约为 30.23。异常放大的影响需要对照实验确认，不能只把失败归因于数据少。

其他待比较因素包括：类别编号作为连续标量、文本与数值的融合方式、缺少显式短时历史、动作转换帧表现、示范覆盖范围。先诊断输入和基线，再比较固定联合头、移动/射击分支或候选评分头。验证集参与模型选择，最终仍需另录独立测试局。

## 公开实现对照

[Qwen-jev 的 model.py](https://github.com/AnubhabBanerjee/Qwen-jev/blob/main/model.py) 使用冻结 Qwen2.5-Coder-1.5B、最后有效 token 池化及 `Linear(1536,2)`，仅 3074 个可训练参数。其任务是函数名与函数体是否匹配的二分类教程，不能据此判断以撒战斗性能。

[TerraBlind](https://github.com/Reisenbug/TerraBlind) 公布了游戏状态、候选生成与控制执行代码，并调用 TypeSafe Jev API；该仓库没有公开 API 后端的决策头结构。具体核对见 [terrablind_review.md](terrablind_review.md)。

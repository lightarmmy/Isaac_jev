# 战斗策略强化学习与主干能力利用

2026-11-25，方案稿。用户反馈 S02 射击意愿低、整体不如 S01，询问强化训练决策头及如何减轻主干能力瓶颈。本轮仅核对代码并提出方案，未启动新训练或游戏交互。

## 已确认的结构与训练限制

1. Qwen3.5-2B 完全冻结，状态由文本主干编码后取最后有效 token 的 2048 维向量。其战术选择能力没有通过原生语言输出单独验证。
2. S02 将固定选项文本单独编码为向量。状态表示、选项向量与候选数值事实在新 MLP 中融合，最终取评分 argmax。共享评分器支持候选重排与子集，但这不证明新敌人、武器、空间关系的泛化。
3. 主要损失仍为人工动作的加权移动/射击交叉熵；S02 另外使用联合动作 NLL。七维质量是实际示范动作的辅助分类目标，部署时不用于直接优化候选的长期收益。
4. 每个观测只知道示范实际执行的动作及后续关联结果。现有数据不提供另外 44 个动作的真实反事实结果；降低坏动作的模仿权重并不会自动教出绕障追击动作。
5. 模型选择采用质量加权验证动作 NLL，尚未使用固定验证局的清房率、受伤量与时间选轮次。因此早期最佳模仿轮次不能视为最佳实机轮次。

不能确认“模型已理解充分”或“训练数据数量过多导致问题”。决策头可以泛化，效果取决于主干表示、候选语义如何进入模型、训练数据支持及优化目标。仅扩大头或替换几层不能保证解决问题。

离线诊断：按动作 ID `% 5 == 0` 统计方向射击释放，S01 验证/测试为 18.39%/18.61%，S02 为 18.10%/13.02%。这不是实际开火/命中率，蓄力武器释放也可产生攻击。S02 实机射击意愿低的反馈需结合具体战况分析，不能用离线总比例否定反馈或直接解释其原因。

## 建议先做的能力分离诊断

选择用户反馈中的追击、障碍遮挡和无效站射状态，使用 Qwen 的预训练语言输出接口及正确 chat template，在相同已观察事实下选择候选。检查其能否识别攻击通道不足、合理绕行和应保持攻击的局面，并用事实变化的成对快照验证其响应。

不要求实时运行长推理文本。诊断用于区分原生语言选择、冻结特征读出与监督目标的作用；原生输出正确也不代表闭环战斗已经可靠。未经抽查或执行验证的教师答案不能直接作为真值。

## 优先路线：已有策略初始化 → 真交互 PPO

先使用 S01/E08 的可用策略初始化 actor，冻结同一主干，新增训练用价值头 V(s)。保持现有输入和动作集合，优先隔离训练目标改变的作用，而不是同时更换结构、文本和奖励。

采样阶段由策略概率分布选择动作，保存行为策略版本、log probability、观测、真实生效动作和持续时间、后续状态及回报。当前部署 argmax 只用于确定性评估，不能照搬为 PPO 的探索采样。

按房间/连续战斗轨迹计算优势，用 PPO 更新 actor/critic；保留少量示范模仿约束或参考策略 KL，早期避免策略快速遗忘。冻结主干仍需对新状态进行前向编码；保存头和训练恢复状态即可。

当前桥接有 4 帧对齐延迟与输入受理/开始执行的区别。奖励必须与实际生效控制对齐，不能把过期或被替换的命令当作执行样本。持续时间变化时应按推进帧处理折扣与收益，无法归属的过渡不能机械用于 actor 梯度。

### 回报与信用分配

| 项目 | 依据与设计 |
| --- | --- |
| 有效输出 | 可信敌人实际 HP 下降，优先补采伤害来源/击杀事件，避免重复 UID、阶段切换和跟班伤害误归因 |
| 清房 | 清房转换及战斗完成事件的一次性奖励，不能每帧重复奖励 clear=True |
| 生存 | 已确认生命损失与死亡惩罚，与输出收益联合权衡 |
| 效率 | 实际推进的战斗时间代价，避免只靠无伤拖延获得高回报 |
| 建立攻击机会 | 可达攻击位置及路径代价等事实构建经过验证的势差，帮助绕障准备获得延迟信用 |

不单独奖励持续移动、按住射击或靠近敌人；这些可产生撞怪、打墙及高速乱跑。无伤也不是每帧正奖励。攻击机会 shaping 使用变化及一次性事件管理，避免反复进退刷“距离改善”；未知穿透/蓄力及无敌阶段保持相应机制信息和证据限制。

PPO 的关键收益是利用后续伤害/清房结果评价前面的换位，而不是仅给已有模仿样本重新打分。价值估计和探索仍可能失败，不能保证少量交互即可学会新战术。

追击绕障涉及多步规划。现有数帧候选几何只能描述局部，建议进一步提供可达攻击位置、路径代价及短期历史/当前目标；若局部反复横跳，比较短期记忆或持续战术目标。事实脚本继续不替策略选动作或拦截动作。

## 其他路线与主干瓶颈

| 方法 | 权重更新与数据 | 主要作用与边界 |
| --- | --- | --- |
| AWR / IQL | 现有连续轨迹，训练价值与 actor | 学相对局面收益；通常受示范支持限制，不能假造未执行动作的收益 |
| 纠错数据 / DAgger / 蒸馏 | 策略失败状态的人类纠正或经核验的教师选择 | 对准追击/绕障等分布缺口；教师须被验证，不能只重复原动作 |
| PPO | 真实策略交互，训练 actor/critic | 可以探索示范未覆盖动作；需要可靠环境、回报和动作执行归属 |
| 原生语言选择 + LoRA | 正确聊天格式、预训练语言输出头及少量适配器 | 将战况与候选放在同一上下文，直接训练语义选择；可再接 PPO/偏好学习 |

如果仅强化决策头仍达不到要求，可改成紧凑的“战况 + 能力说明 + 候选 → 候选 ID”任务，保留预训练语言输出头，并在部分主干层训练 LoRA。候选与状态在主干内进行上下文交互，避免只能由新 MLP 学两份独立向量的匹配。

LoRA 不等于全量训练，也不保证泛化。需要重新计算特征，不能继续沿用冻结 Qwen 的缓存；需重新核验时延、缓存及训练/部署契约。候选名称/顺序变化、未见武器与敌人组合应参与独立验证。结果保存为小头/原生输出配置加适配器，若要求绝对只保存头，则无法让主干表征学习新战术。

## 推荐推进顺序与验收

先用失败快照核验原生 Qwen 的语义选择能力，再以已有可用策略做冻结主干 PPO 对照。若教师正确而小头持续失败，优先考虑经核验的蒸馏或原生输出 LoRA；若教师也失败，修正事实表达并补充战术选择监督，不把问题单纯归给头。

闭环验证按预先固定的独立种子与战况重复运行，比较清房率、每房受伤量、清房时间、长期无进展、有效攻击及伤害发生时的实际控制。按这些验证指标选择轮次，测试局只用于最终评价。动作模仿一致率仍作诊断，不再代替游玩能力。

下一轮应集中验证训练目标/能力读出，不再同时扩展九种配方。在线采样环境需明确可重复训练局与重开方式后才能开始；本提案不启动或接管当前游戏。

# 战斗语义输入与稳健示范方案

状态：讨论稿。2026-11-25。当前服务仍为 V004，本轮整理设计方案。

后续讨论已将实际结果条件与推理目标分开：细粒度质量作为监督标签，不直接输入未来结果，采用统一战斗目标并比较多任务监督与优势加权。本文下方旧示意中的 `Desired outcome condition: positive` 属于原条件模仿契约，不能与新方案混用。最新设计及 TerraBlind/TypeSafe 源码核对见 [细粒度反馈与训练路线](COMBAT_FINE_FEEDBACK_SFT_REVIEW.md)。

## 用户确定的方向

- 充分利用通用语言模型的语义与泛化能力，采用共享的武器能力介绍，不按普通眼泪、蓄力等逐个做专用优化。
- 脚本提供经过计算的高阶事实，让模型主要比较威胁、输出机会和换位价值。
- 运行时脚本不拦截模型动作。事实、动作选择和执行结果分别记录，便于评价模型本身。

## 已核对的现状

V004 和 V005/V006 的敌人、弹幕坐标主要是玩家相对 `dx/dy`。V005/V006 的障碍与地图原点也相对玩家。数值输入仍保留玩家相对房间边界的归一化位置。实体 `vx/vy` 是观测游戏速度，并非所有速度都已转换为玩家相对速度。原始录像保留完整坐标，策略不读取种子或未发现房间的真实内容。

E06/E09 的 `shoot_alignment_estimate` 只检查目标方向、横向偏差（固定 24px）和射程数量，未检查遮挡、攻击传播特性、飞行时延或移动后的射位。E08 使用完整 V005 文本，没有采用这个战术摘要。当前移动风险估计近似瞬时换向、匀速运动，尚未完整覆盖已发送输入、惯性和实际开始执行延迟。

Qwen 当前冻结文本主干，直接 tokenize，做一次前向并取最后有效 token 的 2048 维特征。动作由决策头分类产生，没有自回归的战术推理过程。预训练语义可以帮助状态表征，但不能把修改提示等同于给生成式助手下指令。新文本须在训练与部署使用同一生成器，重新提取冻结特征并训练配套头。

## 核心目标

把“靠近敌人”改成更准确的目标定义：进入或保持安全、有效的攻击位置。距离缩短只有在改善输出机会时才有意义。躲避、换位、维持攻击和充能等待都可能是合理动作，需要结合实际武器能力和威胁关系判断。

## 统一语义接口

### 1. 武器能力说明

用能力属性描述攻击，而非仅给武器编号或笼统名称。建议字段包括攻击触发（持续 / 蓄力释放 / 自动发射）、作用方式（投射物 / 光束 / 接触 / 可控攻击）、瞄准方式、有效范围、目标穿透、障碍穿透、追踪 / 返回等能力，以及当前已观测的充能状态。取值依据实际遥测和已核实的道具知识，未知保持 unknown，保留来源。

将几何事实和武器语义分开：脚本可以报告“玩家与目标之间有石头”，语言模型再结合“攻击能否穿石头”理解其影响。不能将玩家通行图直接当作攻击阻挡图。坑、石头、墙、可破坏物与前方敌人的攻击交互各不相同。

该接口共享于多种武器，不承诺从名称自动获得正确机制，也不将复杂攻击轨迹都硬编码成普通眼泪的直线。

### 2. 高阶战况关系

从完整可观察状态计算简短、可核对的关系：

| 关系 | 支持的判断 |
|---|---|
| 玩家与目标间的距离、相对接近趋势、遮挡类别 | 是否需要换位，以及接近是否改善攻击机会 |
| 可伤害状态、目标群与攻击通道 | 当前攻击是否有有效对象，是否处于合理等待阶段 |
| 各移动方向的通行余量、接触余量、弹幕迫近 | 宽裕绕行与窄缝穿行的差异 |
| 移动后目标遮挡、距离、方向对齐的变化 | 动作如何改变下一时刻的攻击机会 |
| 通向攻击位置的路径关系 | 绕障初期即使远离敌人，仍可能有助于到达射位 |
| 已观察到的敌方血量变化与射位有效性持续时间 | 是否长时间缺乏进展，是否需要重新定位 |

评估候选动作时考虑观测至执行的延迟、残余惯性和正在生效的输入。优先输出“余量充足 / 狭窄 / 明确相交 / 未知”等语义标签，同时保留数值余量与置信来源。近似几何只能作为估计，不能命名为校准后的命中概率或无伤概率。

若计算攻击位置的路径距离，只将其作为事实和特征，不输出 `recommended_action` 或强制跟随的目标点。避免只依据一步的距离变化而困在障碍另一侧。

### 3. 短上下文原则

保留少量、跨武器通用的语义规则：

1. 生存与有效攻击共同构成战斗目标。
2. 迫近的接触或投射物威胁，使脱离威胁具有更高价值。
3. 当前攻击缺乏可达目标时，比较换位带来的攻击机会和风险。
4. 攻击通道有效且环境宽裕时，停留可以合理。
5. 按武器的触发与传播能力解释充能、阻挡和距离关系。
6. 未知机制和几何估计保持不确定性，不自行补成确定事实。

不重复注入大量远处道具描述、整房间字符地图或长篇百科。完整地图和实体留在脚本与原始录像中，模型文本优先表达当前威胁、攻击机会、可用路径及关键能力。

可以增加少量通用情境说明，但不写一成不变的“正确方向是向下”，不再次注入上一移动 / 射击类别作为预测捷径。

### 输入形式示意

```text
Objective: survive while making useful progress against enemies.

Weapon capabilities:
  Trigger: continuous / charge_release / auto / unknown
  Attack behavior: projectile / beam / contact / controlled / unknown
  Obstacle traversal, range and targeting: observed or verified properties

Observed relations:
  Current attack channels: reachable targets and obstruction categories
  Immediate threats: closing contacts and approaching projectiles
  Available routes: broad passages and fragile gaps
  Candidate moves: changes in clearance, occlusion and attack geometry
  Recent progress: observed changes, with unknown attribution preserved

Principles:
  Escape immediate danger. Seek useful attack positions when attack access is poor.
  Keep an effective position when it remains safe. Interpret geometry using weapon capabilities.

Desired outcome condition: positive.
Choose movement and shooting controls.
```

这是一种文本结构示意，不是已有模型输出或实机判定。每帧应填入实际事实，不将所有枚举或相互矛盾的状态一起发送。

## 极限走位的数据处理

2026-11-25 补充：除稳健性外，将数据质量扩展为生存、躲弹、躲接触、攻击机会、实际进展和相对输出效率，并同步讨论监督条件、分支权重与掩码。详见 [多维质量标注与训练监督方案](COMBAT_MULTI_OBJECTIVE_LABEL_PROPOSAL.md)。E03/E09 已有弱进展/威胁距离权重，下一轮应在此基础上做证据与归因的细分；不将现有 negative 条件模仿误称为直接惩罚坏动作。

成功穿过怪物缝隙不能简单改成 negative。操作可能依赖精确碰撞尺寸、无敌帧、击退、提前清掉的弹幕或下一帧快速改向；模型缺乏这些输入或反应速度时，单个按键切片便难以复现整个操作。

建议保留原 positive / negative / unknown 结果，增加独立的示范稳健性记录：实际轨迹的最小接触余量、是否依赖极快反向输入、是否有无敌 / 击退证据、遥测是否完整，以及动作保持更久后的几何脆弱性估计。缺失的无敌信息要标 unknown，不能假设没有。

降低高度脆弱片段的移动分支权重，保留有效射击监督。保留整个 Boss 房间和成功的高技巧片段，另补充宽裕绕行、主动寻找攻击位置与主动脱墙示范。受伤不能否定该片段的射击方向，命中也不能抵消危险移动。只有姿态、范围和机制可信时，才把“持续无输出”标为低效，否则保留未知。

所有未来轨迹、伤害和敌方 HP 下降只进入标签 / 权重，不进入部署状态事实。

## 第一轮对照

先保留 E08 独立双塔，控制架构变化。V004 和已保留的 E08 作为参照。

| 组别 | 输入 / 训练变化 | 目的 |
|---|---|---|
| A | 共享高阶几何事实，以紧凑字段形式输入，原标注权重 | 量化脚本提供额外事实的作用 |
| B | 同样几何事实，改为能力介绍与战况关系文本，原权重 | 检查语义组织是否改善泛化 |
| C | B 加简短通用战术原则，原权重 | 检查上下文原则是否有独立作用 |
| D | C 加多维质量与示范稳健性，调整分支监督条件、权重与掩码 | 检查安全规避、主动换位和有效输出的监督是否改善战斗 |

每轮保存头，使用相同数据划分、训练随机性和真实输入生成器。由于 A 相对旧模型同时改变事实与文本，它是输入方案整体对照；B/C 的事实和数值通道保持一致，才便于讨论语义组织与原则的影响。

如果需要确认收益是否来自通用 LLM，可以增加使用同样结构化事实的数值模型对照，并报告容量与速度差异。只有语义方案在独立种子、房型或未参与训练的能力组合上稳定改善，才支持 LLM 泛化的结论。

## 后续可选架构

当移动与射击组合仍不一致时，再比较共享参数的 45 个候选动作评分头，使模型共同评估“移动后从哪个方向攻击”。这属于新的头设计，不与第一轮的文本 / 权重改动混在一起归因。

若要真正使用生成式的抽象战术推理，可另设低频战术意图模块（脱离威胁、寻找攻击位置、维持攻击等），由实时动作头执行。它需要独立验证延迟、意图时效、切换稳定性和收益；不是当前冻结编码流程已经具备的能力。

## 评价

离线同时报告动作匹配、对明确阻挡的攻击选择、接触余量、从无攻击机会到有效射位的转换，以及 Boss / 普通房分组。几何指标明确标为代理指标。

实机固定种子、人物与装备进行重复比较，记录每房 HP 损失、清房时间、长期无进展 / 打墙时长、实际输入覆盖与接管。敌方 HP 下降按稳定 UID 审计，跟班、毒伤和变身等来源不明时保留归因未知。停留比例和持续移动比例都不作为独立优化目标。

## 实现优先级与未决项

先审计现有录像能支持的多维质量、来源归因与极限示范，再实现能力说明、高阶事实、共享文本生成器及对应标注/监督方案，最后训练第一轮对照。若需隔离输入与监督变化，采用多维标注文档中的四组交叉对照。维护独立输入版本、知识与规则哈希。控制编码长度和本地构建耗时，用真实 RPC 核对，不能通过刷新旧观测帧延长决策寿命。

仍需确认：哪些攻击能力能可靠地从当前遥测读出，哪些需要冻结知识；旧录像能否恢复无敌 / 反向改向依赖；如何定义足够稳健的余量阈值；语义关系组织是否确实优于同样事实的紧凑字段。阈值应在训练 / 验证集上确定，测试集留作最终评估。
